SCOUT — Candidate Fit Scorer: Privacy Policy

Effective date: September 24, 2026 · Publisher: Navitas Business Consulting, Inc.

SCOUT is a browser extension for Navitas recruiters. It reads candidate profiles on LinkedIn and Dice, scores how well each candidate fits open job requisitions, and, when the recruiter asks, adds the candidate to Navitas's applicant tracking system (JazzHR). This policy covers what data the extension handles, why, and where it goes.

1. Who can use SCOUT

SCOUT is an internal recruiting tool. It works only with Navitas's SCOUT backend service and JazzHR account. It is not meant for the general public.

2. Data the extension handles

SCOUT does not collect the recruiter's browsing history, read pages other than LinkedIn and Dice, track the recruiter across websites, or include analytics, advertising, or tracking code.

3. Where data is sent

  • Navitas SCOUT backend (hosted on Microsoft Azure). Candidate profile data is sent here for scoring. When the recruiter clicks to add a candidate, the profile, the résumé, and the JazzHR session token are also sent. All traffic uses HTTPS.
  • JazzHR. The SCOUT backend passes candidates that recruiters choose to add on to Navitas's JazzHR account.
  • Hugging Face (huggingface.co). The extension downloads a public language model (all-MiniLM-L6-v2) once and keeps it in the browser cache. Skill matching then runs on the recruiter's own computer. No candidate data is sent to Hugging Face.

SCOUT does not sell, rent, or share data with any other third party.

4. What is stored in the browser

  • Session storage, which is cleared when the browser closes: the candidate being viewed and the fit scores already calculated, so the panel doesn't have to calculate them again.
  • Local storage: a cache of job requisition titles and descriptions, so the panel opens quickly. No candidate data is kept in local storage.
  • Cache storage: the downloaded language model files.

Removing the extension deletes all of this data. Recruiters can also clear it through the browser's site-data settings.

5. Retention

Candidates added to JazzHR are kept according to Navitas's recruiting records policy and the JazzHR account settings. Profile data sent only for scoring, for candidates who are not added, is used to calculate the score and is not kept as a candidate record.

6. Browser permissions

  • activeTab, scripting: read the LinkedIn or Dice profile in the current tab.
  • storage: the session and local caches described above.
  • sidePanel: show the SCOUT panel next to the page.
  • offscreen: run the local language model and read résumé PDFs in a hidden extension page.
  • cookies: read the JazzHR session cookie described in section 2, and nothing else.
  • Host access: linkedin.com, dice.com (profile pages); api.jazz.co (JazzHR session); the SCOUT backend; huggingface.co (model download).

7. Security

All data is sent over HTTPS. Only authorized Navitas personnel can access the SCOUT backend and JazzHR.
